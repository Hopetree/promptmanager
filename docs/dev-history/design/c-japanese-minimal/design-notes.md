# 设计说明 · 方向 C｜japanese-minimal（和式极简）— dsh 自选

> 阶段 10A 打样稿。**不是产品代码**。依据技能：`frontend-design` + `design-system` + `japanese-minimal` + `web-artifact-designer`。
> 设计稿：`mockup.html`｜截图：`shots/`（5 张）
> **为什么选它**（用户要求说明理由）：见 §1.2。

## 1. 方向与理由

### 1.1 一句话方向

**「把 prompt 当文稿来管」**：米白纸感底 + **明朝体**标题 + 细线分区 + 一枚朱红印章；
文字行距 1.9，像一张安静的写字台。

### 1.2 为什么在 10 种风格里挑它（三个理由 + 一个已处置的风险）

1. **它换的是"字体性格"，不是只换颜色**。方向 A（深色 SaaS）与 B（苹果极简）都属"现代克制"家族，
   差别主要在明暗与留白密度；而 promptmanager 的核心材料就是**文本**——用户一天里花最多时间的动作是
   *读和写一段文字*。明朝体标题、1.9 行距的正文，直接服务于这件事；这是三个方向里唯一在**排版性格**上
   与现状（全黑体、1.45 行距）产生根本差异的方向。
2. **与 A/B 在情绪轴上正交，三选一才有意义**：A = 技术密集的夜间操作台；B = 消费级明亮的陈列；
   C = **安静的写作台**。用户要做的是"选一个性格"，所以这三者必须不同质。
3. **信息层级用"线"而不是"面"来表达**：细线网格在亮暗下都成立，**不需要渐变、不需要阴影**，
   天然满足"亮暗跟随系统"这条硬约束，也符合 FR-40 的"克制"。
4. **风险已在设计前识别并处置**：`frontend-design` 技能明确警告"**米白 + 高对比衬线 + 陶土色**"是 AI 默认观感之一。
   本方向采取三条反制（下一节详述）：纸色**冷调化**、朱红**印章化且 ≤2 处**、加**竖排落款**这个独有签名。

## 2. 反"AI 默认观感"的三处刻意决策（本方向最关键的部分）

| 默认观感的做法 | 本方向的做法 | 为什么 |
| --- | --- | --- |
| 暖奶油底（`#F4F1EA` 一类）+ 陶土色点缀 | 纸色取**冷调近白** `#fbfbf8`；点缀用**朱红 `#b7282e`**（不是陶土/砖红/橙棕） | 把"旧纸"改成"新纸"，避开"复古手账"的模板感 |
| 大标题用高对比衬线（细字重或黑体混排） | 明朝体 **400 字重 + 0.06em 字距**，只用于**页面/条目标题**，字号克制（32/16.5px） | 衬线只做"点题"，不做"喊话"；正文仍是黑体（可读性优先） |
| 装饰性点缀到处撒 | 朱红**只允许两处**：品牌**印章**与**收藏标记**；导航/页签的当前态一律用墨色下划线 | 点缀一多就变成"配色方案"，不再是"重点" |
| （额外） | **竖排落款**：左栏底部「整 理 之 所」与编辑器头「原 稿」用 `writing-mode: vertical-rl` | 这是本风格技能里"可选的高级手法"，用它做**独有签名**——A/B 不可能出现这个元素 |

## 3. 色彩（亮色为规范形态，暗色 = 墨色纸推导）

### 3.1 亮色

| 语义 | 值 | 用途 |
| --- | --- | --- |
| paper | `#fbfbf8` | 页面底（**冷调近白**，不是奶油色） |
| paper-raised | `#ffffff` | 输入区、弹窗（"纸"的层次靠极小的明度差） |
| paper-sunken | `#f4f4f0` | 表头/代码块底 |
| line / line-strong | `#dcdcd6` / `#c8c8c0` | 1px 细线（**全站唯一的"边"**） |
| ink | `#16181a` | 近黑（带一点冷，不是纯黑） |
| ink-muted | `#4a4a45` | 正文/次级 |
| ink-subtle | `#6f6f68` | 说明、标签 |
| vermilion | `#b7282e` | **唯一点缀色**：印章 + 收藏标记（≤2 处/屏） |
| success / link | `#4a6047` / `#2f4a6b` | 语义（missing 0 / 可点文本）——都是**低饱和**的，不与朱红抢 |

### 3.2 暗色（"墨色纸"）

| 语义 | 值 |
| --- | --- |
| paper / paper-raised / paper-sunken | `#101112` / `#161718` / `#0b0c0d` |
| line / line-strong | `#2a2b2c` / `#3a3c3d` |
| ink / ink-muted / ink-subtle | `#f2f1ea` / `#b9b6ab` / `#8d8a80` |
| vermilion | `#d4483f`（提亮以保证暗底对比） |
| success / link | `#8fae8a` / `#9db8d8` |

**为什么暗色要推导**：`japanese-minimal` 技能验收项写"背景为米白或纯白，**无纯黑背景**"。但 FR-40 要求
亮暗跟随系统不得回归 → 本方向把暗色定义为"**墨色纸**"（近黑的冷灰，不是纯黑 `#000`），
既满足"无纯黑"，也让同一个"纸"的隐喻在暗处延续。这是对技能的一处有意识偏离，已记在 §9.1。

## 4. 字体与字号阶梯

- **衬线（明朝体）**：`"Hiragino Mincho ProN","Yu Mincho","Noto Serif SC","Songti SC","Source Han Serif SC","Noto Serif CJK SC",SimSun,"Droid Sans Fallback",Georgia,serif`
  → 用于：页面标题、条目标题、统计数字、弹窗标题、变量渲染结果。
- **黑体（sans）**：`"Hiragino Kaku Gothic ProN","Yu Gothic","PingFang SC","Noto Sans SC","Microsoft YaHei","Droid Sans Fallback",system-ui,sans-serif`
  → 用于：正文、表格数据、按钮、标签、输入框（**输入仍是黑体**：长时间书写时明朝体小字号偏累）。
- **等宽**：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` → 版本号、日期、diff、id。

| 角色 | 字号 / 行高 / 字重 / 字距 | 用在哪 |
| --- | --- | --- |
| 页面标题 h1 | 32 / 1.4 / 400 / **+0.06em** | 「Prompt の 目録」 |
| 编辑器标题 | 24 / 1.4 / 400 / +0.08em | 「会话交接模板」 |
| 条目标题 | 16.5 / 1.6 / 400 / +0.04em | 列表里的 prompt 名（衬线） |
| 统计数字 | 26 / 1.2 / 400 / +0.04em | 九 / 三 / v3 / 0.3ms |
| 正文 | 15 / **1.8** / 400 / 0 | 表单、说明 |
| 输入区 | 14.5 / **1.9** / 400 / +0.03em | textarea（衬线，书写感） |
| 小标签 | 11 / 1.4 / 400 / **+0.22em** | 「文 庫」「標 籤」（用字距做"印章体"感） |
| 数据 | 12 / 1.4 mono | 版本、日期 |

**关键**：全站没有一处 `font-weight > 500`；标题不加粗，靠**字号 + 字距 + 衬线**立起来。

## 5. 间距节奏（「間」）

- 4px 基数，但**大方差**：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`；
- 区块之间 **32–48**（本方向原规范是营销页尺度 ≥96，管理界面按 app 尺度下调，见 §9.2）；
- 行距是"间距的一部分"：正文 1.8、输入区 1.9 —— 在中国用户的小屏上也不挤；
- 列表行 56px（介于 A 的 38 与 B 的 60 之间）：够松，又不浪费；
- 页面右侧保留 90–120px 空白（`max-width:1120` + 64 padding）——这是有意的「間」，不是没对齐。

## 6. 圆角 / 描边 / 阴影

- 圆角：**几乎不用**——输入/按钮 3px、卡片 4px、弹窗 0（方角）。本方向的"边"是**线**，不是圆角。
- 描边：1px `--line`；只在"输入框/按钮/分隔"用；**没有粗边框、没有彩色边框**（除朱红按钮）。
- 阴影：**全站无阴影**（弹窗用 1px 强描边 + 半透明遮罩区分层级）。这是技能明确禁止项。
- 纹理/渐变：无（唯一的"装饰"是印章与竖排落款）。

## 7. 信息层级与重点（列表与编辑器是主战场）

- **列表页**：焦点是**条目标题（衬线）**；表头用字距拉开的小字（「標 題 / 標 籤 / 文 庫」）当"栏目名"；
  数据列用等宽小字；操作（改訂/削除）只在 hover 出现。列表**没有卡片**——整页就是一张纸上的目录，
  靠细线切分行。
- **编辑器**：左侧表单是"稿纸"（衬线输入 + 大行距），右侧检查器列（改訂履歴 diff / 変数の埋め込み / Markdown 表示）
  与 A/B 同构（三方向共有的结构提案：把"切 tab"变常驻）；编辑器头部有**竖排「原稿」**标记。
- 一屏只有一个实心按钮（保存 / 新規作成），其余是细描边；破坏性动作（replace 清空）用朱红实心。

## 8. 动效（克制到什么程度）

**基本没有**：只有输入框/按钮的 `border-color` 过渡（技能明确"无动画"）；
`prefers-reduced-motion` 下全关。悬停没有位移、没有放大、没有阴影变化——页面是"静"的。

## 9. 与现状的差异点（现状 = 只用 `theme.algorithm`、零 token 定制、纯 antd 默认外观）

| 维度 | 现状（阶段 8 交付） | 方向 C |
| --- | --- | --- |
| 字体性格 | 全站黑体，14px/1.5 | **明朝体标题 + 黑体数据 + 1.8–1.9 行距** |
| 画布 | 纯白/纯黑 + 默认卡片 | **冷调纸白 `#fbfbf8`** / 墨色纸，无卡片、无阴影 |
| 分隔 | antd 默认边框 + 表格竖线 | **1px 细线，全站唯一的"边"**；表格无竖线 |
| 点缀色 | antd 蓝（含标签/按钮到处用） | **朱红只 2 处**（印章 + 收藏），导航/页签当前态用墨色 |
| 圆角 | 8px 卡片圆角 | 近乎直角（3–4px），弹窗方角 |
| 识别元素 | 无 | **朱红印章**（品牌）+ **竖排落款**（整理之所 / 原稿） |
| 数字表达 | 与正文同字体 | 统计数字用**衬线**（九/三），数据用等宽 |

## 10. 落地到 antd 的注意点（详见 `tokens.md`）

- `fontFamily` 必须是**黑体栈**（antd 全局正文），衬线只在需要的组件上用 `style` 局部指定
  （页面标题/条目标题/统计数字/弹窗标题）——**不要**把全局 `fontFamily` 换成衬线，否则表格/表单会难读。
- 无阴影：`boxShadow: 'none'`、`card.boxShadowTertiary: 'none'`、`Modal.boxShadow: none` +
  `Modal` 用 `border: 1px solid <line-strong>`（一处少量 CSS 或 `styles` 属性）。
- 圆角压到最小：`borderRadius: 3`、`borderRadiusLG: 4`、`borderRadiusSM: 2`。
- 字段名用小字距标签：`label` 用 `style={{letterSpacing:'0.22em', fontSize:11}}`（少量内联）。
- **印章与竖排落款**：两个 26px/13px 的元素，用 `Layout.Header` 内的一个 `div` + `writing-mode` 实现（少量 CSS，不改组件库）。

## 11. 已识别的风险 / 偏差（如实记录）

1. **暗色是推导**（技能原文偏向"无深色"）：做法是"墨色纸"而非纯黑，已记 §3.2。
2. **间距按 app 尺度下调**（技能原规范 ≥96px 区块间距是营销页尺度）：管理界面取 32–48，否则一屏两行。
   保留了行距（1.8–1.9）与右侧留白，所以"間"的观感还在。
3. **字体可得性（最实际的风险）**：明朝体依赖系统字体。**228 上只有 `Droid Sans Fallback`**（无衬线），
   所以本机截图里的中文标题**看不到明朝体**（西文 "Prompt" 能看到衬线）。若 10B 选 C，需要用户在三条里拍板：
   ① 就用系统衬线栈（macOS/Windows 有 Songti/SimSun，Linux 可能退化成黑体）；② 自托管字体文件（**不是 CDN**，
   体积 +3–8MB）；③ 只把衬线用在少数"点题"位置（本稿的做法，退化也可接受）。
   **本阶段不引任何字体文件**（约束：零外链）。
4. **朱红纪律容易被后人破**：一旦有人给"标签"加彩色、给危险按钮之外的地方上朱红，这个方向立刻变廉价。
   因此 §2 表格与 `tokens.md` §6 都写了"禁止清单"。
5. **密度**：56px 行 + 1.8 行距比 A 松，1280 下一屏约 9–10 行（A 约 12+，B 约 7–8）——居中。
