# 设计说明 · 方向 B｜apple-minimal（苹果极简白）

> 阶段 10A 打样稿。**不是产品代码**：只描述方向与决策，落地在阶段 10B（用户挑选后）。
> 依据技能：`frontend-design` + `design-system` + `apple-minimal`（风格规范）+ `web-artifact-designer`。
> 设计稿：`mockup.html`｜截图：`shots/`（5 张）

## 1. 一句话方向 + 为什么适合这个产品

**「把 prompt 当作品陈列」**：纯白画布 + 超大细字重标题 + 大留白 + 极淡阴影的大圆角卡片，
唯一交互色是系统蓝；数据用"目录"而不是"密集表格"来呈现。

为什么适合 promptmanager：prompt 是有价值的**文字资产**，用户会反复阅读、修改、挑版本。
这个方向用"陈列"的心态对待每一条 prompt：标题大而轻（17px/500）、行高 60px、卡片浮在浅灰底上，
整个界面没有一处硬边和重线。它给"管理工具"带来的是**从容感**——打开就想读一读手里的东西。
代价是密度低于方向 A：1280 下一屏能看到的条目更少（这正是它的取舍，不是缺陷）。

## 2. 色彩（亮色为规范形态，暗色按同一原语对称推导）

### 2.1 亮色

| 语义 | 值 | 用途 |
| --- | --- | --- |
| canvas | `#ffffff` | 页面底（纯白） |
| canvas-alt | `#f5f5f7` | 内容区底（让白卡片浮起来） |
| surface / surface-soft | `#ffffff` / `#fbfbfd` | 卡片 / 卡片内输入区 |
| hairline | `#e8e8ed` | 1px 行分隔（**只在表格行之间，不做竖线**） |
| ink | `#1d1d1f` | 主文字（近黑，不用纯黑） |
| ink-muted | `#6e6e73` | 次级文字 / 表格单元格 |
| ink-subtle | `#6e6e73` | 说明、列标题（**刻意从技能给的 `#86868b` 改深**，见 §10.1） |
| accent | `#0066cc` | 唯一交互色：链接、编辑/删除、收藏星、主按钮底（用 ink） |
| accent-hover | `#0071e3` | hover |
| success / danger | `#1d7d3f` / `#c7251f` | 语义色（missing 0 / 删除） |

### 2.2 暗色（推导，非另起一套）

| 语义 | 值 |
| --- | --- |
| canvas / canvas-alt | `#000000` / `#0d0d0f` |
| surface / surface-soft | `#161617` / `#101011` |
| hairline | `#2d2d2f` |
| ink / ink-muted / ink-subtle | `#f5f5f7` / `#a1a1a6` / `#a1a1a6` |
| accent | `#2997ff`（暗底上等价可读的蓝） |
| success / danger | `#30d158` / `#ff3b30` |

**为什么暗色要自己推导**：`apple-minimal` 技能明确写"深色请路由到 dark-saas"。但 **FR-40 要求亮暗跟随系统不得回归**，
所以本方向给出"同原语反转"的暗色版本（黑白互换 + 蓝提亮），而不是把用户甩给另一个方向。
这是对技能的一处**有意识的偏离**，理由是规格优先（`frontend-design` 也讲"brief 的明确要求优先"）。

## 3. 字体与字号阶梯

- **字体**：`-apple-system, BlinkMacSystemFont, "SF Pro Text", Inter, "Helvetica Neue", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", "Droid Sans Fallback", sans-serif`
  （系统栈优先——**不引 CDN 字体**）。
- **不用 700**：本方向靠"**大 + 细**"高级，不是靠加粗。

| 角色 | 字号 / 行高 / 字重 / 字距 | 用在哪 |
| --- | --- | --- |
| 页面标题 h1 | **40 / 1.08 / 600 / -0.021em** | 「Prompt 库」（本方向的性格来源） |
| 编辑器标题 | 28 / 1.15 / 600 / -0.021em | 「会话交接模板」 |
| 统计数字 | 28 / 1.1 / 600 / -0.02em | 09 / 03 / v3 |
| 列表标题 | **17 / 1.4 / 500 / -0.012em** | 每条 prompt 的名字（列表的主角） |
| 正文/表单 | 15 / 1.5 / 400 | 表格单元格、toolbar |
| 说明文字 | 12.5–13 / 1.5 / 400 | 副标题、统计标签、脚注 |
| 数据（mono） | 12.5–13 mono | 版本、日期、取用次数 |

**层级手法**：靠**字号跨度**（40 → 17 → 12.5）而不是靠颜色/边框制造层级；全屏只有黑白灰 + 一点蓝。

## 4. 间距节奏

- 「留白即设计」：区块间距 32–48，页面内边距 32/64；**行高 60px** 让每条 prompt 有呼吸。
- 本方向原规范是营销页尺度（区块 ≥96px）；**管理界面按 app 尺度下调**（32/48），但保留了"大留白"的比例感。
  这是对技能的第二处有意识调整（技能场景是 landing page，本产品是高频工具），已在 §10.2 记录。
- 4px 基数阶梯：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。

## 5. 圆角 / 描边 / 阴影

- 圆角：卡片 **18**、输入 **12**、胶囊按钮/筛选器 **980（全圆）**、标签 980。
- 描边：几乎没有——只有 1px 行分隔（`#e8e8ed`）与输入框的默认描边；**表格没有竖线**。
- 阴影：**极淡**（`0 4px 24px rgba(0,0,0,.08)`），只在"浮起来的白卡片"上；暗色下改为 `rgba(0,0,0,.6)`。
- 渐变：只用在品牌标记（24px 小方块），其余**无渐变、无玻璃拟态**（技能禁用项）。

## 6. 信息层级与重点（列表与编辑器是主战场）

- **列表页**：主战场是"**条目本身**"。页面标题 40px 是视觉入口，但真正的主角是每条 17px 的 prompt 名 +
  60px 行高构成的"目录"。筛选控件（胶囊）刻意低对比；统计条只用大数字不画框。
  行内操作（编辑/删除）**hover 才出现**，避免每行都挂两个按钮。
- **编辑器**：左侧"白纸"表单（输入区用 `#fbfbfd` 而非描边，聚焦才出现蓝边），右侧检查器列
  （版本历史 / 变量填值 / Markdown 预览）与 A 方向同构——**把"切 tab"变成"常驻上下文"**，这是三方向共有的结构提案。
- 一屏一个主 CTA（近黑胶囊"保存（生成 v4）"），危险动作用红字/红底，其余都是蓝字或灰胶囊。

## 7. 动效（克制到什么程度）

只有 `220ms cubic-bezier(.28,.11,.32,1)` 的 `background/color/border/opacity` 过渡；hover 有轻微提亮，
**没有位移/缩放/视差/入场序列**。已声明 `prefers-reduced-motion` 全关。
（`frontend-design` 提醒"过度动效是 AI 味来源"——本方向刻意接近"静止"。）

## 8. 与现状的差异点（现状 = 只用 `theme.algorithm`、零 token 定制、纯 antd 默认外观）

| 维度 | 现状（阶段 8 交付） | 方向 B |
| --- | --- | --- |
| 页面层级 | 16px 标题 + 工具条 + 表格，层级扁平 | **40px 细字重标题** + 大留白，层级强烈 |
| 列表形态 | 密集表格（39px 行、竖线分隔） | **目录式**：60px 行、无竖线、17px 标题、hover 出操作 |
| 卡片 | antd 默认 8px 圆角 + 默认阴影 | 18px 圆角 + 极淡阴影，浮在 `#f5f5f7` 上 |
| 按钮 | antd 默认矩形按钮 | **胶囊**（980px），主按钮近黑底白字 |
| 强调色 | `#1677ff` 到处用（含标签） | 蓝只给**交互**；标签是中灰胶囊（不给标签上色） |
| 关闭/危险 | antd 默认红 | 红只用于破坏性动作（删除、清空重建） |
| 编辑器 | 抽屉 + Tab 切换 | 白纸表单 + **常驻检查器列** |

## 9. 落地到 antd 的注意点（详见 `tokens.md`）

- 大圆角 + 胶囊：`borderRadiusLG: 18`、`Button.borderRadius`/`borderRadiusSM: 980`（**用 token 而不是 CSS 覆盖**）。
- 表格去竖线：`Table.headerSplitColor: 'transparent'` + `borderColor` 用 hairline；行高靠 `cellPaddingBlock: 18`（≈60px）。
- 大标题**不要**用 `Typography.Title level={1}` 的默认字号（38px/600 但行高与字距不同），
  建议用 `Typography.Title` + `style={{fontSize:40,letterSpacing:'-0.021em',fontWeight:600}}`（只此一处内联，属"少量自定义"）。
- 输入区"无描边、有底色"：`Input.colorBgContainer` + `activeBorderColor`；`variant="filled"` 直接可用。

## 10. 已识别的风险 / 偏差（如实记录）

1. **可读性偏差（刻意）**：技能给的 `--ink-subtle: #86868b` 在白底只有约 3.5:1，**不达 WCAG AA 4.5:1**。
   本稿把次级文字改深到 `#6e6e73`（≈4.9:1），并在暗色用 `#a1a1a6`（≈8:1）。
   代价是"轻"的感觉略减；收益是表格里的小字真正可读。**这是一处主动的、可回退的偏离**。
2. **密度偏差（刻意）**：技能原规范是营销页尺度（区块 ≥96px、正文 17–21px）。管理界面按 app 尺度下调（32/48、15px），
   否则 1280×800 一屏只能放 4–5 条。`design-notes` 与 `tokens.md` 都按下调后的值给。
3. **亮色是本方向的规范形态**，暗色是推导；暗色下"极淡阴影"的表达力下降（黑底看不出阴影），
   因此暗色主要靠 `#161617` 卡片与 `#000` 画布的对比分层（截图 `list-dark.png` 已体现）。
4. **大留白吃屏幕**：1280×800 下列表一屏约 7–8 行（方向 A 可 12+）。若用户主要在笔电小屏用，需在 10B 把行高降到 52–56。
5. 本机无 SF Pro/Inter，截图西文为系统回退字形；中文字形三方向一致（Droid Sans Fallback）。
