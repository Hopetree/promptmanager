## Q-1 视觉重设计方向：请在 A / B / C 中挑一个（2026-09-18 20:05）

- **为什么需要你定**：BRIEF v11 **FR-40** 明确要求"先定方向 → 打样 → **经用户挑选后**铺开"；
  这是纯产品取舍（美学口味），规格把选择权给了你，dsh 不自行拍板——**选错方向会让阶段 10B 的全站落地整体返工**。
  打样已做完（三套自包含设计稿 + 令牌草案 + 各 5 张截图），现在只差你点一个。
- **候选方案**：
  - **A｜dark-saas（Linear 式深色 SaaS）**：*工程师的夜间操作台*——近黑画布 + 表面色阶 + 唯一薰衣草蓝 `#5e6ad2`，信息密度最高（1280 一屏 12+ 行）。
    适合"长时间盯、要专业工具感"；代价：亮色形态不如暗色有性格、分类标签不能上色。截图 `docs/design/a-dark-saas/shots/`
  - **B｜apple-minimal（苹果极简白）**：*把 prompt 当作品陈列*——纯白 + 40px 细字重标题 + 胶囊按钮 + 18px 大圆角卡片，观感最"贵"。
    适合"主要在 1920+ 大屏、喜欢松弛留白"；代价：密度最低（一屏 7–8 行）。截图 `docs/design/b-apple-minimal/shots/`
  - **C｜japanese-minimal（和式极简）—— dsh 推荐**：*把 prompt 当文稿来管*——纸感底 + 明朝体标题 + 1.8 行距 + 细线分区 + 一枚朱红印章 + 竖排落款。
    **唯一改"字体性格"的方向**，与 A/B 在情绪轴上正交，且层级靠"线"而非"面/阴影"，亮暗都不需要重新设计。截图 `docs/design/c-japanese-minimal/shots/`
    唯一风险：中文衬线依赖系统字体（本机截图里看不到明朝体，西文能看到）——10B 可选：① 系统衬线栈 ② 自托管字体（**不引 CDN**，+3–8MB） ③ 只在标题等点题处用衬线。
  - **（可选）混搭**：例如"要 C 的排版 + A 的暗色"、"要 B 的大标题 + A 的高密度"。
    这类需求**不需要重做打样**，写清组合即可，10B 会在令牌层面对齐（`docs/design/*/tokens.md` 的三层结构就是为混搭准备的）。
- **建议顺序**：**C > A > B**（理由：C 差异化最大且亮暗成本最低；A 落地最稳、密度最高；B 观感最好但吃屏幕）。
